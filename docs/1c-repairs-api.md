# Заказ-наряды: подключение расширения 1С

Первый этап: агрегатор принимает полную карточку ремонта и показывает все карточки
одним списком в разделе «Заказ-наряды». Автомобиль в этом этапе — только
наименование контрагента из документа. Новые карточки идут первыми по дате
документа; при одинаковой дате порядок определяется UUID. Номер и автомобиль
не являются уникальными: разные документы с одинаковыми реквизитами сохраняются
отдельно. Состав запчастей и вход сотрудников по коду в этот контракт не входят.

## Серверные настройки

Используется существующая `GARAGE_DB_PATH`: отдельная таблица `repair_cards`
создаётся автоматически, без изменения строк или схемы гаража, корзины и
уведомлений. Данные сохраняются после перезапуска и доступны с разных компьютеров.
Сохраняйте эту базу между обновлениями. Резервные копии делайте SQLite backup API
или при остановленном сервисе; при работающем сервисе учитывайте WAL/SHM.

На сервере агрегатора задайте отдельную переменную окружения
`ONEC_REPAIRS_INTEGRATION_SECRET`. Допустимы 32–256 символов ASCII: латинские
буквы, цифры, `_`, `-`. Рекомендуется сгенерировать 32 случайных байта, например
`node -e "console.log(require('node:crypto').randomBytes(32).toString('base64url'))"`,
и поместить результат в менеджер секретов или защищённое окружение службы.
Не помещайте значение в исходники, `.env.example`, журналы, URL или браузер.
Приложение не загружает `.env` автоматически. После изменения секрета перезапустите
службу. Пустое/отсутствующее значение отключает только приём из 1С (`503`);
чтение списка и остальные функции продолжают работать. Некорректное непустое
значение останавливает запуск с ошибкой конфигурации без вывода самого секрета.

Для Bearer-аутентификации отправитель также должен знать секрет. Храните его
в защищённых серверных настройках 1С и выполняйте HTTP-запрос на сервере 1С;
не передавайте его клиентской форме и не зашивайте в код расширения. Это отдельный
секрет, независимый от учётных данных поставщиков и master key шифрования.
Агрегатор получает его только из окружения, не сохраняет в SQLite, не возвращает
в API и не загружает во frontend.

Сервер по-прежнему слушает loopback. Для удалённого сервера 1С используйте HTTPS
через доверенный reverse proxy с проверкой сертификата. Для маршрута приёма
настройте передачу `Authorization` и доступ сервера 1С без интерактивного входа
в веб-интерфейс. Не открывайте таким исключением остальные `/api/*`: их текущая
пользовательская аутентификация остаётся на reverse proxy. Для `/api/repairs`
действуют те же ограничения доступа, что и для существующего интерфейса.
Дополнительный CORS не включается. Исключите заголовок Authorization и тела
запросов из журналов reverse proxy/1С.

## Приём одной карточки

`POST /api/integration/1c/repairs`

Заголовки:

```http
Authorization: Bearer <секрет из серверных настроек>
Content-Type: application/json; charset=utf-8
```

Тело — ровно один JSON-объект в UTF-8 без BOM. Массивы, `null`, дополнительные
поля, неполные карточки и параметры URL отклоняются. Лимит тела — 16 KiB
(16 384 байта). Все пять полей обязательны и являются непустыми строками:

| Поле | Формат и ограничение | Источник в 1С |
| --- | --- | --- |
| `documentId` | UUID с дефисами, 36 символов, не нулевой; регистр не важен, хранится в нижнем | Строка UUID ссылки документа, не его номер |
| `number` | До 64 символов | Номер документа, включая префиксы и ведущие нули |
| `date` | Реальная дата `YYYY-MM-DDTHH:mm:ss`, ровно 19 символов | Дата и время документа в часовом поясе базы 1С |
| `vehicleName` | До 500 символов | `Контрагент.Наименование`, без сборки марки/VIN/госномера |
| `status` | До 200 символов | Текущее текстовое представление состояния ремонта |

Начальные и конечные пробелы строк удаляются; управляющие символы запрещены.
Ограничения длины проверяются до удаления пробелов, в кодовых единицах UTF-16.
Дата не содержит `Z` или смещение часового пояса. Она хранится без преобразования
и показывается как в 1С (`ДД.ММ.ГГГГ ЧЧ:мм`); секунды сохраняются в API/SQLite.
Пустое наименование или состояние не заменяются вымышленным значением: перед
отправкой заполните их в источнике. Статус передаётся дословно, без словаря
агрегатора и без автоматического исключения завершённых ремонтов.

Структура JSON ниже — шаблон контракта, значения в угловых скобках нужно заменить
реальными данными. Шаблон сам по себе не является валидной карточкой:

```json
{
  "documentId": "<UUID ссылки документа 1С>",
  "number": "<номер документа>",
  "date": "<YYYY-MM-DDTHH:mm:ss>",
  "vehicleName": "<наименование контрагента>",
  "status": "<состояние ремонта>"
}
```

Успешный ответ для создания и обновления: `200 OK`, `Cache-Control: no-store`.

```json
{
  "repair": {
    "documentId": "<UUID документа в нижнем регистре>",
    "number": "<номер документа>",
    "date": "<YYYY-MM-DDTHH:mm:ss>",
    "vehicleName": "<наименование контрагента>",
    "status": "<состояние ремонта>"
  }
}
```

UUID является первичным ключом SQLite. Повторная отправка выполняет атомарный
`INSERT ... ON CONFLICT ... DO UPDATE`: заменяет все четыре реквизита карточки,
сохраняя одну запись. Последний успешно принятый запрос определяет данные;
версионность и сравнение времени изменения документа пока отсутствуют. Поэтому
передавайте обновления одного UUID последовательно и не повторяйте устаревшую
карточку после новой. Контракт рассчитан на одну базу 1С.

При сетевом обрыве/таймауте результат может быть неизвестен отправителю: безопасно
повторить ту же полную карточку с тем же UUID. Для временных `500`/`503` применяйте
ограниченные повторы с паузой, сохраняя порядок по UUID; при `503` сначала проверьте
настройку интеграции. Ошибки `400`/`401`/`413`/`415` требуют исправления данных или
настроек. Отправляйте карточки после успешной записи документа; внешнюю сеть
не следует включать внутрь транзакции его записи.

## Чтение списка

`GET /api/repairs` — без тела и параметров URL. Используется интерфейсом агрегатора,
не требует секрета интеграции и наследует существующий доступ через reverse proxy.
Ответ: `200 OK`, `Cache-Control: no-store`.

```json
{ "repairs": [] }
```

При наличии данных `repairs` содержит полные объекты с теми же пятью полями.
Список полный, без пагинации, фильтрации или скрытого ограничения количества.
Интерфейс загружает его при открытии раздела и по кнопке «Обновить».

## Ошибки

Любая прикладная ошибка возвращает JSON вида `{ "message": "Описание ошибки" }`,
без stack trace, содержимого запроса, секретов и внутренних путей.

| HTTP | Значение |
| --- | --- |
| `400` | Некорректный JSON/карточка, невозможная дата или параметры URL |
| `401` | Секрет отсутствует или неверен; заголовок `WWW-Authenticate: Bearer` |
| `405` | Недопустимый HTTP-метод; допустимый указан в `Allow` |
| `413` | Тело превышает 16 KiB |
| `415` | Content-Type отличается от application/json |
| `500` | Ошибка чтения/записи SQLite; данные не подменяются пустым успехом |
| `503` | На сервере не задан секрет интеграции |

Неверный секрет проверяется до разбора тела, сравнение выполняется через
`timingSafeEqual` по SHA-256 дайджестам одинаковой длины. Шлюз может отдельно
возвращать собственные ошибки TLS, сетевого доступа и аутентификации.

## Проверка подключения на реальных данных

1. Настройте серверный секрет и HTTPS-маршрут, сохраните прежнюю `GARAGE_DB_PATH`.
2. Выберите существующий записанный заказ-наряд и передайте пять фактических полей.
3. Откройте «Заказ-наряды»: проверьте номер, дату, наименование контрагента и состояние.
4. Измените состояние в 1С и передайте карточку с тем же UUID; останется одна строка.
5. Перезапустите агрегатор и снова откройте список: карточка должна сохраниться.

Эта реализация добавляет принимающую сторону агрегатора. Она не изменяет XML/BSL
расширения, не подписывается на события документов 1С и не выполняет исходную
выгрузку автоматически. Код отправки в расширении подключается к описанному API.
