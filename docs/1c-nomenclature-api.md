# Номенклатура из 1С: наличие и карточка по коду

После сканирования агрегатор создаёт краткоживущий запрос к одному подключению 1С.
Расширение 1С забирает его исходящим HTTPS-запросом, находит товар и текущие цены,
отправляет результат. Браузер получает карточку из агрегатора. Видео
обрабатывается на телефоне. При открытии раздела отдельное задание читает страницу
товаров в наличии без расчёта цен. Полной выгрузки номенклатуры и входящих соединений к базе нет.

## Подключение

### Остаток и история после сканирования

Новая карточка показывает остаток с учётом заказов, четыре месяца реализации
(текущий и три предыдущих), затем три цены. Все числа приходят в том же ответе
по штрихкоду, дополнительного задания или запроса статистики нет.

Товар в `products` допускает необязательное поле `statistics`:

```json
{
  "stockWithOrders": 7.125,
  "unit": "шт",
  "monthlySales": [
    { "month": "2026-11", "quantity": 3 },
    { "month": "2026-10", "quantity": 0 },
    { "month": "2026-09", "quantity": -1 },
    { "month": "2026-08", "quantity": 12 }
  ]
}
```

`stockWithOrders` — тот же расчёт, что в карточке 1С: складские остатки минус
положительная потребность каждого заказа покупателя, результат не меньше нуля.
Реализация — `КоличествоОборот - КоличествоИнтОборот` регистра «Продажи»;
возвраты сохраняют отрицательный знак. В обоих показателях суммируются все
характеристики, склады и организации; цены остаются для найденной характеристики.
`unit` — базовая единица хранения или `null`.

`monthlySales` содержит ровно четыре последовательных месяца в порядке убывания,
название месяца строится в браузере из `YYYY-MM` без сдвига часового пояса.
Границы периода определяет дата сеанса 1С: до конца сегодняшнего дня, без будущих
дней месяца. Отсутствие оборотов даёт нулевой месяц. Нет прав на нужный регистр —
`stockWithOrders` или `monthlySales` равны `null`; ошибка чтения не заменяется нулём.
Отсутствие `statistics` или `statistics: null` сохраняет совместимость со старыми
расширениями и ранее полученными результатами. Неверные/неполные данные отклоняются.

В локальном расширении карточка номенклатуры дополнена пятым месяцем: текущий
и четыре предыдущих. Штатный прогноз закупки **и карточки, и списка** использует
этот период по сегодняшний день, с прежним учётом заказов, поставок и областей
организация/склад/характеристика. Отображаемое среднее делится на
`4 + день месяца / число дней в месяце`, чтобы неполный месяц не считался полным.
Ключи кэша прогноза обновлены, границы истории включены в подпись списка.
Это подготовленные исходники, функциональная проверка в 1С ещё требуется.

### Порядок настройки

1. Обновить агрегатор, сохранив существующий файл `GARAGE_DB_PATH`. Новые таблицы
   добавляются автоматически при старте. Обычная резервная копия этой базы должна
   включать новые настройки; при работающем SQLite использовать его backup API.
2. Войти администратором и открыть «Настройки → Номенклатура».
   Создать ключ и скопировать его в настройки номенклатуры в 1С.
   После закрытия настроек ключ повторно не отображается. При потере создать новый.
3. В 1С в существующих настройках агрегатора указать `https://aggregator.kovlab.com`
   без завершающего пути.
   Заполнить новый ключ номенклатуры и три вида цен: закупочный, розничный,
   розничный безналичный. Сохранить настройки: серверное задание подключается
   автоматически, отдельного флажка включения поиска нет.
   Вид безналичной цены первоначально берётся из соответствующей константы расширения.
4. На сервере 1С разрешить выполнение регламентных заданий. После обновления
   расширения один раз сохранить настройки интеграции. Предопределённое задание
   `АС_ПоискНоменклатурыАгрегатора` работает круглосуточно с интервалом и паузой
   2 секунды. Оно обрабатывает до 20 запросов за цикл с сетевым сроком 45 секунд;
   после ошибки очереди выдерживает паузу 30 секунд. Платформа не запускает это
   задание параллельно самому себе. Открытые клиенты и форма настроек не нужны.
   При первом сохранении назначается учётная запись администратора, сохраняющего
   настройки; уже назначенная служебная запись сохраняется. Она должна оставаться
   действующей и иметь доступ к запуску задания. HTTPS должен быть доступен с сервера 1С.
5. На телефоне открыть «Номенклатура» и считать известный код. Сверить название,
   характеристику и три цены с карточкой 1С. Штрихкод показан компактно над карточкой,
   рядом кнопка «Копировать». «Повторить поиск» заново запрашивает тот же код.
   Чтения с фотографии нет. В окне камеры фонарик включается по умолчанию,
   кнопка справа сверху выключает и включает его, если это поддерживает устройство.

Адрес компьютера/сервера 1С не задаётся в агрегаторе. База обращается к нему по HTTPS.
Подключается одна база: не использовать один ключ в разных базах одновременно,
иначе задания будут распределяться между ними. Копия базы требует повторного
сохранения настроек: отпечаток подключения блокирует унаследованный обработчик.
Флажок «Тестовый обмен заказ-нарядами» относится только к заказ-нарядам.
Подключение номенклатуры и его ключ от этого режима не зависят.
Для работы без пользователей нужна серверная база; клиентского таймера поиска больше нет.
Локальная файловая база поддерживается для проверки с открытым клиентом 1С.
Режим совместимости расширения остаётся 8.3.27. Собственные регламентные задания
расширений поддерживаются платформой [начиная с 8.3.23](https://v8.1c.ru/platforma/news/novoe-v-platforme-8-3-23/).
HTTPS обязателен.

## Диагностика в 1С

Основная форма содержит адрес, ключи, три вида цен, включение обмена заказ-нарядами
и краткое состояние. Кнопка «Для разработчиков» открывает отдельную форму,
доступную только пользователю с полными правами. Сначала сохраните изменения основной формы.

- «Состояние сервера и очереди — JSON» показывает назначение и расписание задания,
  последние 10 запусков, ошибки и очередь заказ-нарядов. Включённое задание само по
  себе не подтверждает выполнение: если запусков нет, проверьте блокировку заданий
  в настройках сервера и действительность назначенной учётной записи.
- «Проверить ключ и HTTPS — JSON» показывает фактический ответ `/status`.
  `ready` подтверждает ключ, `workerOnline` — недавние обращения обработчика очереди,
  `lastSeenAt` — время последнего обращения. Проверка ключа не обновляет это время.
- Локальная проверка штрихкода с тремя тестовыми видами цен возвращает этап,
  ошибку либо JSON карточки. Тестовые значения не сохраняются и данные на сайт не отправляются.
  Ключ и подключение для локального чтения не требуются.
- Проверка выбранного заказ-наряда формирует JSON без отправки. Тестовый режим
  заказ-нарядов, повторная выгрузка и удаление карточек перенесены сюда же;
  отправка и удаление требуют подтверждения, смена режима — отключённого обмена.

Ключи и секреты не включаются в диагностику. JSON карточки содержит реальные
данные выбранного товара или заказ-наряда; доступ к форме проверяется на сервере.

## Переход с двух подключений

Обновить агрегатор и исходники расширения вместе: пути API изменились.
При первом запуске сохраняется ключ прежней базы по умолчанию. Если настроено
только одно подключение, сохраняется его ключ. Второй ключ отзывается. Начатые
запросы завершаются ошибкой, их нужно повторить. Последующие запуски не меняют
ключ. Старые пути `test`/`production` возвращают 404 и не забирают задания.

## Ключи и права

Используется один ключ номенклатуры. Генерация
нового ключа и отключение подключения немедленно отзывают старый, завершают его
ожидающие запросы ошибкой. Агрегатор хранит SHA-256 ключа; полный ключ возвращается
лишь при создании. 1С хранит его в серверном безопасном хранилище БСП и не возвращает
в форму. Ключ номенклатуры не заменяет `ONEC_REPAIRS_INTEGRATION_SECRET`.

Пользователь с правом «Номенклатура» видит все три цены, включая закупочную.
Настройки подключений доступны только администратору. Результат поиска доступен
создавшему его пользователю и администратору. Все ответы канала — `Cache-Control: no-store`.
Не вставлять ключи в URL, журналы, скриншоты и исходники.

## API браузера

Все маршруты требуют текущую авторизованную сессию и право на раздел.
Настройки и подключения требуют администратора.

| Метод и путь | Назначение |
| --- | --- |
| `GET /api/nomenclature/connection` | `{ configured, online, lastSeenAt }` |
| `GET /api/nomenclature/settings` | То же состояние для администратора |
| `POST /api/nomenclature/connection` | Администратор: тело `{}`; создать/заменить ключ, однократно вернуть `token` вместе с состоянием |
| `DELETE /api/nomenclature/connection` | Администратор: отозвать ключ |
| `POST /api/nomenclature/lookups` | `{ "barcode": "2000043626425" }`, ответ 202 с `lookup` |
| `GET /api/nomenclature/lookups/{id}` | Текущее состояние и продукты |
| `DELETE /api/nomenclature/lookups/{id}` | Отменить активный поиск |
| `GET /api/nomenclature/stock?q={text}&after={uuid}` | Порция товаров в наличии с поиском; для первой порции `after` отсутствует, пустой `q` означает всё наличие |

Состояния `lookup.status`: `pending`, `found`, `not_found`, `error`, `expired`,
`cancelled`. До результата `products` пуст. Запрос содержит `id`,
исходный `barcode`, `createdAt` и `expiresAt` в UTC ISO-8601.
Ведущие нули и содержимое кода сохраняются; строка должна быть непустой, до
200 символов, без управляющих символов. Это точный поиск штрихкода, не поиск по
артикулу и не переход по URL из QR.

Подключение считается активным, если 1С забирала задания или отправляла ответы
в последние 90 секунд. Обработчик может законно занимать до 45 секунд на чтение
и подготовку страницы, поэтому оставлен запас на завершение одного длительного
запуска. Ненастроенный/недоступный источник возвращает 503, не
подменяется другой базой. До 3 активных запросов на пользователя и до 100 на
подключение; превышение — 429. Неизвестные поля и неверные типы отклоняются.

## API обработчика 1С

Здесь используется отдельная авторизация `Authorization: Bearer <ключ номенклатуры>`.
Сессия пользователя не нужна. Неверный или отозванный ключ — 401.

`GET /api/integration/1c/nomenclature/status` возвращает
`{ "ready": true, "workerOnline": false, "lastSeenAt": null, "stockVersion": null, "stockReady": false }` для принятого ключа
без обращений обработчика. После получения заданий `workerOnline` становится `true`,
а `lastSeenAt` содержит время последнего обращения в UTC ISO-8601. Через 90 секунд
без обращений `workerOnline` становится `false`. Сам `/status` не обновляет это время.

`ready` подтверждает ключ, `workerOnline` — недавнее обращение обработчика.
Они не подтверждают поддержку списка: старое расширение может обслуживать только
штрихкоды. `stockVersion` показывает максимальную версию `stock` среди опросов
последних 90 секунд: 0 — только штрихкоды, 1–4 — прежние варианты списка,
5 — текущие фильтры, цены и счётчик. `stockReady` означает наличие обработчика
версии 5; это проверка протокола, а не успешности запроса к регистрам 1С.
Проверка `/status`, отправка результата и неверный ключ не объявляют возможности.
После перезапуска агрегатора версия неизвестна до первого опроса; смена ключа
сбрасывает её. Одновременный опрос старого обработчика не отменяет возможности
недавно подключённого нового.

Если известный обработчик не поддерживает требуемый вариант списка, браузерный
GET сразу возвращает 503 с кодом `stock_unsupported` и просьбой обновить расширение
в базе и перезапустить задание поиска. Задание в очередь не добавляется.
Если GET начался до первого опроса, объявление несовместимой версии освобождает
ожидание и отменяет невостребованное задание. Штрихкоды и поддерживаемые старые
варианты запросов остаются доступны; фильтры не отбрасываются ради совместимости.

В локальном исправлении обработчика его общий лимит остаётся 45 секунд,
но опрос оставляет 30 секунд на чтение и доставку принятого задания. Поэтому
пустое ожидание в начале запуска длится максимум 15 секунд. Проверка срока,
настроек и отказ от устаревших результатов сохраняются. Изменения исходников
начинают действовать только после отдельного обновления расширения в базе.

`GET /api/integration/1c/nomenclature/requests?waitSeconds=20`
ожидает до 20 секунд (допустимо 0–20), возвращает `{ "request": null }` либо:

```json
{
  "request": {
    "id": "11111111-1111-4111-8111-111111111111",
    "leaseId": "22222222-2222-4222-8222-222222222222",
    "barcode": "2000043626425",
    "expiresAt": "2026-11-09T12:00:30.000Z"
  }
}
```

UUID и даты здесь иллюстрируют формат. Запрос живёт 30 секунд после создания.
Получение выдаёт его одному обработчику с арендой на 10 секунд. После истечения
аренды незавершённый запрос может быть выдан снова с новым `leaseId`; результат
от прежнего обработчика тогда отклоняется. Не более двух параллельных ожиданий
на подключение. HTTP-таймаут ожидания должен быть больше `waitSeconds`.

`POST /api/integration/1c/nomenclature/results`, JSON до 64 КиБ:

```json
{
  "requestId": "11111111-1111-4111-8111-111111111111",
  "leaseId": "22222222-2222-4222-8222-222222222222",
  "status": "found",
  "products": [{
    "id": "33333333-3333-4333-8333-333333333333",
    "name": "Пример товара",
    "characteristicId": null,
    "characteristicName": null,
    "prices": {
      "purchase": { "amount": 6500, "currency": "RUB" },
      "retail": { "amount": 8800, "currency": "RUB" },
      "retailCashless": { "amount": 9750, "currency": "RUB" }
    }
  }]
}
```

`found` требует 1–20 товаров. При отсутствии — `not_found` и `products: []`,
при ошибке чтения — `error` и `products: []`. Оба поля характеристики либо null,
либо UUID/наименование. Повторение одной пары товар/характеристика запрещено.
Все три поля цен обязательны: значение null означает отсутствие записи, 0 —
действительную нулевую цену. Сумма — конечное число 0–10¹², валюта — код ISO
из трёх заглавных латинских букв. Ни UUID, ни числовой штрихкод не передавать числами.

Успех: 200 `{ "accepted": true, "requestId": "…" }`. Повтор полностью
одинакового результата с тем же `leaseId` безопасен. Изменённый повтор,
чужое задание, заменённая аренда, отменённый или истёкший запрос — 409.
Некорректный формат — 400, неверный Content-Type — 415, большой JSON — 413.
Ошибки не раскрывают внутренние исключения. История результатов удаляется
при обращении к очереди спустя 24 часа после срока запроса; это не каталог товаров.

## Страницы товаров в наличии

Обновлённый обработчик обращается к прежней очереди с параметром
`GET /api/integration/1c/nomenclature/requests?waitSeconds=20&stock=4`.
`stock=4` подтверждает сортировку всего результата и поиск по частям.
`stock=3` подтверждает поиск по всем частям в любом порядке. `stock=2`
получает только запросы из одной части (прежний поиск подстроки), а `stock=1`
сохраняет прежний обмен наличием, но получает только порции без поисковой строки:
старый обработчик не может молча проигнорировать фильтр. Без параметра `stock`
выдаются только прежние задания поиска по штрихкоду. Обработчикам `stock=1/2/3`
не выдаются задания с выбранной сортировкой: они не должны молча вернуть
технический порядок вместо запрошенного.
Штрихкоды и страницы обслуживаются по времени создания заданий. Дополнительного
обработчика, фоновой полной выгрузки и отдельного опроса склада нет.

Задание страницы для `stock=3` имеет поля `{ kind: "stock", id, leaseId, after, query, limit: 100,
expiresAt }`. `after` — UUID последнего показанного товара либо null.
`query` — строка поиска (пустая означает весь список); в ответах `stock=1` поле
отсутствует. В браузерном GET параметр `q` — до 100 символов без управляющих
символов. Агрегатор нормализует Unicode NFC, крайние/повторные пробелы и регистр
до постановки в очередь. Части разделены пробелами, повторы удалены, порядок
канонизирован: «кол тор» и «ТОР кол кол» дают один ключ очереди `кол тор`.
Каждая часть должна встретиться в наименовании или артикуле (между частями И,
между полями ИЛИ). «кол тор» находит оба порядка «Тормозные колодки»/
«Колодки тормозные», но не «Колодка реле». `%`, `_`,
`[`, `]` и `~` экранируются и ищутся буквально, SQL-текст из ввода не строится.
Без выбора колонки источник использует порядок ссылок 1С; сравнивать UUID как
строки в браузере или Node.js нельзя. Срок задания — 30 секунд, аренда — 10 секунд.

Для браузера `sort=name|article|quantity`, `direction=asc|desc`. По умолчанию
`sort=id&direction=asc` — прежний технический порядок. Другие значения и повторы
параметров запрещены. Сортировка выполняется в 1С до ограничения порции:
по исходному наименованию/артикулу или по сумме фактического остатка. При
одинаковых значениях дополнительный ключ — ссылка по возрастанию, в обоих
направлениях основной колонки. Правила сравнения строк принадлежат СУБД/1С.

Задание `stock=4` дополнено `sortField`, `sortDirection`; `after` теперь null
либо `{ id: UUID, value: string|null }`. При `id` значение null. Для текста это
исходное значение реквизита последней строки **до** очистки для отображения;
пустой артикул допустим. Для `quantity` это точная строка JSON-числа 1С, например
`"1.125"`, а не округлённый браузерный Number. Подзапрос по справочнику ограничивает
текстовый диапазон до группировки; сравнение суммы применяется в `ИМЕЮЩИЕ`.
Результат дополнен `lastSortValue` того же типа: при продолжении сортированного
списка оно обязательно, для `id` и ошибки null; в последней порции допустимо null.
Один ключ формируется на порцию, дополнительных полей на каждом товаре нет.

Результат отправляется в `POST /api/integration/1c/nomenclature/stock-results`,
JSON до 256 КиБ, с тем же ключом Bearer:

```json
{
  "requestId": "11111111-1111-4111-8111-111111111111",
  "leaseId": "22222222-2222-4222-8222-222222222222",
  "status": "completed",
  "products": [{
    "id": "33333333-3333-4333-8333-333333333333",
    "name": "Пример товара",
    "article": "0000123",
    "quantity": 1.125
  }],
  "hasMore": false,
  "lastSortValue": null
}
```

На странице 0–100 уникальных товаров. `hasMore: true` допускается только
при 100 строках. UUID непустой; название до 500 символов, артикул до 50,
без управляющих символов. Пустой артикул допустим, ведущие нули сохраняются.
Расширение подготавливает отображаемые названия, характеристики и артикулы:
управляющие символы становятся границами слов, смежные границы не создают пустые
фрагменты. Например, `Колодки\r\n\t тормозные` передаются как `Колодки тормозные`.
Это только копии реквизитов для передачи: справочник 1С не записывается,
товары не пропускаются, ссылки/остатки/цены не изменяются. Если обязательное
название после очистки пустое, остаётся явная ошибка; проверка строки поиска,
штрихкода и входящего JSON агрегатора сохраняется строгой.
Остаток — конечное положительное число до 10¹⁵. Ошибка — `status: "error"`,
`products: []`, `hasMore: false`; неполный список не принимается за успех.
Подтверждение и идемпотентный повтор имеют тот же формат, что у поиска.
Чужая аренда, отмена, изменённый повтор и просроченное задание возвращают 409.

Браузер делает один GET страницы: агрегатор ожидает событие результата без
повторных HTTP-опросов и отвечает `{ products, hasMore, nextCursor, receivedAt }`.
`nextCursor` без сортировки равен UUID последней строки при `hasMore: true`;
при сортировке это непрозрачная строка `s1.…` до 8192 символов, иначе null.
Клиент передаёт её целиком в `after` без разбора. Составной курсор связан с поиском,
колонкой и направлением; их смена требует начала с первой порции. Курсор не
заменяет проверку прав доступа и не создаёт исторический снимок остатков.
`receivedAt` — время приёма агрегатором, а не момент единого снимка базы 1С.
Тот же доступ `nomenclature` проверяется до постановки задания; отдельного
административного разрешения на чтение не требуется. Это общий складской каталог
подключённой базы, без ограничения по ответственности сотрудника/организации.

Совпадающие незавершённые `query/after/sort/direction` объединяются, до 100 ожидающих HTTP-запросов
и 20 различных страниц на процесс. Закрытие последнего читателя отменяет задание;
закрытие одного из нескольких не мешает остальным. Смена ключа/отключение источника
завершает ожидание ошибкой и отзывает прежние ответы. После завершения страницы
новое открытие/обновление создаёт новое задание: межзапросного кэша остатков нет.
История заданий удаляется при обращении к очереди/загрузке через минуту после
истечения срока. Ошибки связи — 503, превышение нагрузки — 429, срок ожидания — 504.

В 1С один запрос к `ЗапасыНаСкладах.Остатки` получает реквизиты и сумму
`КоличествоОстаток` по номенклатуре, объединяя склады, организации, характеристики,
партии и ячейки. Отбор суммы > 0 применяется после суммирования, отрицательные
измерения не отбрасываются заранее. Исключены группы, помеченные на удаление
и номенклатура другого типа, кроме `ТипыНоменклатуры.Запас`. Резервы не вычитаются,
пересчёта упаковок нет: количество в базовой единице хранения товара. Это
фактическое наличие, а не обещание свободного количества для продажи.

Поисковый отбор всех частей применяется внутри параметров виртуальной таблицы остатков
через подзапрос по справочнику номенклатуры, до суммирования и ограничения 101.
Поэтому товар из конца каталога находится без загрузки предыдущих порций.
Для пустой строки нет поискового подзапроса. Подстрочный поиск может требовать
сканирования справочника: наличие индекса артикула не обещает ускорение `%текст%`.
Количество частей ограничено общей длиной строки 100 символов (до 50 непустых
односимвольных частей). На часть готовится свой параметр, отдельных SQL-чтений
по частям нет; запрос выполняется один раз на порцию.

`ПЕРВЫЕ 101` ограничивает полученный набор: 100 строк передаются, 101-я означает
следующую страницу. Цены/штрихкоды/объекты товаров в цикле не читаются. Следующие
страницы отбираются по последнему значению и ссылке, без растущего OFFSET и без
запроса общего количества. Без выбора колонки используется технический порядок ссылок.
Порции читают текущие данные независимо: изменения склада между ними
не дают единого исторического снимка, кнопка обновления начинает просмотр заново.

В интерфейсе нет кнопок страниц. `IntersectionObserver` запрашивает следующую
порцию за 400 пикселей до конца списка; одновременно активен один GET. При
смене поиска старый GET отменяется сразу, результаты очищаются; следующий
запрос начинается через 300 мс после ввода либо сразу по Enter. Для длинного
списка в DOM остаются до трёх порций/300 товарных строк, остальные заменены
измеренными отступами. Прокрутка вверх использует уже полученные данные без
повторного чтения 1С. Память данных растёт с числом загруженных товаров.
Ошибка следующей порции сохраняет предыдущие строки, останавливает автоматику
и показывает «Повторить загрузку». Обновление/новый поиск очищают весь список.
Пустой/оборванный ответ HTTP отображается понятным сообщением, с кодом статуса
при HTTP-ошибке, без сырого исключения JSON и без автоматических повторов.
При начальной ошибке сообщение показывается один раз.
Клик по заголовку сразу отменяет прежний GET, очищает строки и запрашивает первую
порцию в новом порядке. Шапка остаётся доступной при загрузке, пустом результате
и ошибке; выбранная колонка и направление показаны стрелкой и `aria-sort`.

Ограничение количества строк не означает чтение всего 101 исходного остатка:
СУБД может обрабатывать и группировать оставшийся диапазон регистра. Фактический
план и время проверяются в рабочей базе, ускорение без этого не заявляется.
Журнал `АС_Агрегатор.НоменклатураОстатки` фиксирует число строк, `hasMore` и время
чтения/подготовки, без ключей и описаний товаров.

Проверки: `tests/nomenclature-stock.test.mjs` (обмен, границы, конкурентность,
отмена, ошибки и число заданий) и `tests/browser/nomenclature-stock.test.mjs`
(автозагрузка, страницы, мобильная таблица и сохранение прежнего сканирования
в отдельном наборе). Для рабочей проверки обновить агрегатор и исходники
расширения, открыть раздел, сверить остатки по одному товару на разных складах,
нулевой/отрицательный итог, пустой артикул, дробное количество и резервы.
Повторить переходы по большому списку и одновременное открытие у сотрудников,
сопоставить журнал с временем до появления таблицы. Платформа 1С локально
не запускалась; статические проверки не заменяют эту сверку.

## Данные 1С и ограничения поиска по коду

Поиск выполняется по `РегистрСведений.ШтрихкодыНоменклатуры.Штрихкод` и
`Справочник.ШтрихкодыУпаковокТоваров.ЗначениеШтрихкода`. Удалённые товары,
группы и удалённые упаковки исключены. Партия/единица из штрихкода не меняют
выбранную цену: карточка показывает цены из регистра для товара/характеристики,
без пересчёта упаковки и без редактирования данных базы.

Три роли сопоставляются с явно выбранными ссылками `Справочник.ВидыЦен`.
Используется `ЦеныНоменклатуры.СрезПоследних` на дату сеанса, с актуальностью,
действующим видом цен и точной характеристикой. Произвольная другая характеристика
не подставляется. Валюта берётся из записи цены, иначе из вида цен. Формулы
не пересчитываются — передаётся сохранённая текущая цена. Поддержанный в расширении
набор валют: RUB, USD, EUR, CNY, KZT, BYN, GBP, AED, JPY, CHF, TRY; неизвестная или
неуказанная валюта даёт ошибку, а не вымышленную сумму в рублях.

В платформе 1С проверить: известный EAN/QR, код с ведущими нулями, отсутствующий
код, несколько совпадений/характеристик, отсутствующую и нулевую цену, три
назначенных вида цен, недоступную 1С, замену/отключение ключа и независимость
от тестового режима заказ-нарядов. Автоматические
проверки агрегатора используют временные базы и модель обработчика; запуск
расширения в реальной платформе и сборка CFE выполняются отдельно пользователем.
