# Номенклатура из 1С по считанному коду

После сканирования агрегатор создаёт краткоживущий запрос к одному подключению 1С.
Расширение 1С забирает его исходящим HTTPS-запросом, находит товар и текущие цены,
отправляет результат. Браузер получает карточку из агрегатора. Видео
обрабатывается на телефоне. Полной выгрузки номенклатуры и входящих соединений к базе нет.

## Подключение

1. Обновить агрегатор, сохранив существующий файл `GARAGE_DB_PATH`. Новые таблицы
   добавляются автоматически при старте. Обычная резервная копия этой базы должна
   включать новые настройки; при работающем SQLite использовать его backup API.
2. Войти администратором и открыть «Настройки → Номенклатура».
   Создать ключ и скопировать его в настройки номенклатуры в 1С.
   После закрытия настроек ключ повторно не отображается. При потере создать новый.
3. В 1С в существующих настройках агрегатора указать `https://aggregator.kovlab.com`
   без завершающего пути, включить «Поиск номенклатуры включён».
   Заполнить новый ключ номенклатуры и три вида цен: закупочный, розничный,
   розничный безналичный. Сохранить, нажать «Проверить подключение номенклатуры».
   Вид безналичной цены первоначально берётся из соответствующей константы расширения.
4. Оставить клиентский сеанс 1С открытым. Его таймер каждые 2 секунды запускает
   отдельное фоновое задание, если оно ещё не работает. Задание обрабатывает до
   20 запросов за цикл с сетевым сроком 45 секунд; после ошибки пауза 30 секунд.
   Закрытие формы настроек не останавливает поиск. Закрытие всех клиентов прекращает
   новые запуски; поддержка непрерывной работы без клиента потребует отдельного
   регламентного задания и не входит в этот этап.
5. На телефоне открыть «Номенклатура» и считать известный код. Сверить название,
   характеристику и три цены с карточкой 1С. Штрихкод показан компактно над карточкой,
   рядом кнопка «Копировать». «Повторить поиск» заново запрашивает тот же код.
   Чтения с фотографии нет. В окне камеры фонарик включается по умолчанию,
   кнопка справа сверху выключает и включает его, если это поддерживает устройство.

Адрес компьютера/сервера 1С не задаётся в агрегаторе. База обращается к нему по HTTPS.
Подключается одна база: не использовать один ключ в разных базах одновременно,
иначе задания будут распределяться между ними. Копия базы требует повторного
сохранения настроек: отпечаток подключения блокирует унаследованный обработчик.
Флажок «Тестовый обмен заказ-нарядами» относится только к заказ-нарядам.
Подключение номенклатуры, его ключ и включение поиска от этого флажка не зависят.
Для номенклатуры допускается и файловая база; HTTPS обязателен.

## Переход с двух подключений

Обновить агрегатор и исходники расширения вместе: пути API изменились.
При первом запуске сохраняется ключ прежней базы по умолчанию. Если настроено
только одно подключение, сохраняется его ключ. Второй ключ отзывается. Начатые
запросы завершаются ошибкой, их нужно повторить. Последующие запуски не меняют
ключ. Старые пути `test`/`production` возвращают 404 и не забирают задания.

## Ключи и права

Используется один ключ номенклатуры. Генерация
нового ключа и отключение подключения немедленно отзывают старый, завершают его
ожидающие запросы ошибкой. Агрегатор хранит SHA-256 ключа; полный ключ возвращается
лишь при создании. 1С хранит его в серверном безопасном хранилище БСП и не возвращает
в форму. Ключ номенклатуры не заменяет `ONEC_REPAIRS_INTEGRATION_SECRET`.

Пользователь с правом «Номенклатура» видит все три цены, включая закупочную.
Настройки подключений доступны только администратору. Результат поиска доступен
создавшему его пользователю и администратору. Все ответы канала — `Cache-Control: no-store`.
Не вставлять ключи в URL, журналы, скриншоты и исходники.

## API браузера

Все маршруты требуют текущую авторизованную сессию и право на раздел.
Настройки и подключения требуют администратора.

| Метод и путь | Назначение |
| --- | --- |
| `GET /api/nomenclature/connection` | `{ configured, online, lastSeenAt }` |
| `GET /api/nomenclature/settings` | То же состояние для администратора |
| `POST /api/nomenclature/connection` | Администратор: тело `{}`; создать/заменить ключ, однократно вернуть `token` вместе с состоянием |
| `DELETE /api/nomenclature/connection` | Администратор: отозвать ключ |
| `POST /api/nomenclature/lookups` | `{ "barcode": "2000043626425" }`, ответ 202 с `lookup` |
| `GET /api/nomenclature/lookups/{id}` | Текущее состояние и продукты |
| `DELETE /api/nomenclature/lookups/{id}` | Отменить активный поиск |

Состояния `lookup.status`: `pending`, `found`, `not_found`, `error`, `expired`,
`cancelled`. До результата `products` пуст. Запрос содержит `id`,
исходный `barcode`, `createdAt` и `expiresAt` в UTC ISO-8601.
Ведущие нули и содержимое кода сохраняются; строка должна быть непустой, до
200 символов, без управляющих символов. Это точный поиск штрихкода, не поиск по
артикулу и не переход по URL из QR.

Подключение считается активным, если 1С забирала задания или отправляла ответы
в последние 45 секунд. Ненастроенный/недоступный источник возвращает 503, не
подменяется другой базой. До 3 активных запросов на пользователя и до 100 на
подключение; превышение — 429. Неизвестные поля и неверные типы отклоняются.

## API обработчика 1С

Здесь используется отдельная авторизация `Authorization: Bearer <ключ номенклатуры>`.
Сессия пользователя не нужна. Неверный или отозванный ключ — 401.

`GET /api/integration/1c/nomenclature/status` возвращает
`{ "ready": true }`. Он проверяет ключ, но не отмечает
обработчик активным: для этого нужно получение заданий.

`GET /api/integration/1c/nomenclature/requests?waitSeconds=20`
ожидает до 20 секунд (допустимо 0–20), возвращает `{ "request": null }` либо:

```json
{
  "request": {
    "id": "11111111-1111-4111-8111-111111111111",
    "leaseId": "22222222-2222-4222-8222-222222222222",
    "barcode": "2000043626425",
    "expiresAt": "2026-11-09T12:00:30.000Z"
  }
}
```

UUID и даты здесь иллюстрируют формат. Запрос живёт 30 секунд после создания.
Получение выдаёт его одному обработчику с арендой на 10 секунд. После истечения
аренды незавершённый запрос может быть выдан снова с новым `leaseId`; результат
от прежнего обработчика тогда отклоняется. Не более двух параллельных ожиданий
на подключение. HTTP-таймаут ожидания должен быть больше `waitSeconds`.

`POST /api/integration/1c/nomenclature/results`, JSON до 64 КиБ:

```json
{
  "requestId": "11111111-1111-4111-8111-111111111111",
  "leaseId": "22222222-2222-4222-8222-222222222222",
  "status": "found",
  "products": [{
    "id": "33333333-3333-4333-8333-333333333333",
    "name": "Пример товара",
    "characteristicId": null,
    "characteristicName": null,
    "prices": {
      "purchase": { "amount": 6500, "currency": "RUB" },
      "retail": { "amount": 8800, "currency": "RUB" },
      "retailCashless": { "amount": 9750, "currency": "RUB" }
    }
  }]
}
```

`found` требует 1–20 товаров. При отсутствии — `not_found` и `products: []`,
при ошибке чтения — `error` и `products: []`. Оба поля характеристики либо null,
либо UUID/наименование. Повторение одной пары товар/характеристика запрещено.
Все три поля цен обязательны: значение null означает отсутствие записи, 0 —
действительную нулевую цену. Сумма — конечное число 0–10¹², валюта — код ISO
из трёх заглавных латинских букв. Ни UUID, ни числовой штрихкод не передавать числами.

Успех: 200 `{ "accepted": true, "requestId": "…" }`. Повтор полностью
одинакового результата с тем же `leaseId` безопасен. Изменённый повтор,
чужое задание, заменённая аренда, отменённый или истёкший запрос — 409.
Некорректный формат — 400, неверный Content-Type — 415, большой JSON — 413.
Ошибки не раскрывают внутренние исключения. История результатов удаляется
при обращении к очереди спустя 24 часа после срока запроса; это не каталог товаров.

## Данные 1С и ограничения первого этапа

Поиск выполняется по `РегистрСведений.ШтрихкодыНоменклатуры.Штрихкод` и
`Справочник.ШтрихкодыУпаковокТоваров.ЗначениеШтрихкода`. Удалённые товары,
группы и удалённые упаковки исключены. Партия/единица из штрихкода не меняют
выбранную цену: карточка показывает цены из регистра для товара/характеристики,
без пересчёта упаковки и без редактирования данных базы.

Три роли сопоставляются с явно выбранными ссылками `Справочник.ВидыЦен`.
Используется `ЦеныНоменклатуры.СрезПоследних` на дату сеанса, с актуальностью,
действующим видом цен и точной характеристикой. Произвольная другая характеристика
не подставляется. Валюта берётся из записи цены, иначе из вида цен. Формулы
не пересчитываются — передаётся сохранённая текущая цена. Поддержанный в расширении
набор валют: RUB, USD, EUR, CNY, KZT, BYN, GBP, AED, JPY, CHF, TRY; неизвестная или
неуказанная валюта даёт ошибку, а не вымышленную сумму в рублях.

В платформе 1С проверить: известный EAN/QR, код с ведущими нулями, отсутствующий
код, несколько совпадений/характеристик, отсутствующую и нулевую цену, три
назначенных вида цен, недоступную 1С, замену/отключение ключа и независимость
от тестового режима заказ-нарядов. Автоматические
проверки агрегатора используют временные базы и модель обработчика; запуск
расширения в реальной платформе и сборка CFE выполняются отдельно пользователем.
